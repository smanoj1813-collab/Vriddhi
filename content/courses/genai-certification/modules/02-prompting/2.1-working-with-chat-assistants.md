# 2.1 Working with chat assistants: getting real work done

> **Lesson plan** · 75 minutes — Read 25 · Lab 35 · Quiz 15

## Learning objectives

By the end of this lesson you will be able to:

- Use the core features of a modern chat assistant — files, images, voice, web search, memory and sharing — for study and work tasks.
- Manage a conversation deliberately: when to continue, when to start fresh, and how to reset a drifting chat.
- Compare two assistants on the same task and record which is better for what.
- Avoid the five habits that make chat output worse.

## Opening scenario

Two students are asked to summarise a 40-page NEP 2020 policy document for a college seminar. Rahul types "summarise NEP 2020" into a chat window and gets a generic answer from the model's memory — some of it outdated. Sneha uploads the PDF, tells the assistant who the audience is, asks for a one-page summary with page references, and then asks it to list anything it was unsure about. Same tool, same fifteen minutes; only one of them has something usable.

This lesson is about becoming Sneha before we even get to prompt engineering proper.

## Core ideas

### 1. The chat window is more than a text box

Most learners use ten percent of what an assistant can do. The features below exist in all the major assistants, though names differ:

| Feature | What it does | Use it for |
| --- | --- | --- |
| **File upload** | Reads PDFs, Word, Excel, CSV, images. | Summaries, question banks from notes, data analysis, checking your own draft. |
| **Image input** | Understands photos and screenshots. | Explaining a graph, reading a handwritten timetable, describing a poster for feedback. |
| **Web search / browse** | Fetches live pages and (usually) cites them. | Anything time-sensitive — rules, prices, news, recent research. |
| **Voice mode** | Talk instead of type; hear answers. | Language practice, interview rehearsal, thinking aloud while commuting. |
| **Code / data tools** | Runs code in the background to compute, chart, convert. | Arithmetic on lists, quick charts, cleaning a spreadsheet. |
| **Canvas / artifacts** | A side panel for drafting documents or code you edit together. | Long documents, iterative writing, slides outlines. |
| **Memory** | Remembers facts about you across chats (opt-in). | "I am a BBA student in Mysuru" once, not every time. Check what is stored. |
| **Custom assistants** | Saved instructions + knowledge (GPTs, Gems, Projects). | Module 5. |
| **Share / export** | Link to a chat, export to Docs/Word. | Handing work to a teammate or facilitator with the trail intact. |

Spend ten minutes finding each of these in the two assistants you set up in Lesson 1.3. Knowing where the paperclip is matters more than any prompt trick.

### 2. Conversation hygiene

An assistant reads the whole conversation each time it answers (up to its context window). That gives you three rules:

1. **One job per chat.** Mixing your accounting homework and a poster caption in one thread muddles both. Start a new chat for a new job; name it if the tool allows.
2. **Reset when it drifts.** If the assistant keeps repeating a mistake, do not argue for five turns — the wrong content is now in the context and will keep influencing answers. Copy the good parts, open a new chat, and write a better opening prompt.
3. **Put the important information first and last.** Models pay the most attention to the beginning and end of long inputs. Instructions at the top, the question at the bottom, the long document in between.

### 3. Giving the assistant what it cannot know

From Lesson 1.2: the model can only work with what is in front of it. Before you ask anything, supply:

- **Who you are and who the output is for** — "second-year B.Com student; the reader is a faculty member".
- **The material** — upload the file or paste the text instead of asking from memory.
- **The constraints** — length, language, format, what to leave out.
- **The standard** — "university seminar quality", "WhatsApp message to a client", "Instagram caption for a college fest".

You will formalise this in Lesson 2.2. For now, notice that Sneha's success came almost entirely from *context*, not clever wording.

### 4. Comparing assistants honestly

Vendors change their models constantly, so rankings you read online go stale in weeks. Build your own evidence instead: run the same prompt in two assistants and note the difference in a simple log. Over a few weeks you will learn things like "Tool A is better at Kannada, Tool B is better at spreadsheets, both hallucinate case law". That log is more useful than any review, and you will keep it as part of your prompt library (Lesson 2.6).

Dimensions worth comparing:

- **Accuracy** on a fact you can check.
- **Following instructions** — did it respect the word limit and the format?
- **Voice** — does the writing sound like a person or like a brochure?
- **Indian context** — does it know GST, UGC, NEP, the Karnataka SEP, local names and places?
- **Refusals** — does it decline reasonable requests (which happens) or accept unreasonable ones (which also happens)?

### 5. Five habits that make output worse

1. **Vague verbs** — "help me with", "do something about". Say what you want: draft, list, compare, critique, convert.
2. **No audience** — the model defaults to writing for nobody in particular.
3. **Asking two things at once** — split them, or number them.
4. **Accepting the first answer** — the first answer is a draft; the second and third prompts are where quality comes from.
5. **Never saying what was wrong** — "make it better" is useless; "the second paragraph repeats the first, and the tone is too formal for students" is a brief.

## Try it now

Upload any lecture notes or a chapter PDF and run this sequence in one chat:

```text
Turn 1:
You are helping a [second-year BBA] student prepare for an internal exam.
Read the attached notes. First, list the 8 most important concepts in the order
they appear, with the page or section each comes from. Do not explain them yet.
```

```text
Turn 2:
For concepts 1–4, write a 2-line explanation each in simple English, then a
one-line Kannada translation of the key term. Mark anything where the notes
were unclear or incomplete with [CHECK].
```

```text
Turn 3:
Now write 5 exam-style short-answer questions (2 marks each) on these notes,
with model answers of 40–60 words. Mention which concept each question tests.
```

Notice how each turn builds on the previous one, and how the `[CHECK]` instruction forces the assistant to admit uncertainty instead of papering over it.

## Hands-on lab: the same job, two assistants (35 min)

1. **Pick a real task (5 min)** from your Lesson 1.1 audit — something you actually need this week (a report section, a plan for a club event, a summary of a chapter).
2. **Write one opening prompt (10 min)** that includes who you are, who the output is for, the material (upload or paste), the constraints and the standard. Keep the wording identical for both tools.
3. **Run it in two assistants (10 min).** Then, in each, send exactly the same follow-up: *"Rate your own answer out of 10 against my constraints, list what you left out, and revise."*
4. **Log the comparison (10 min)** in a sheet with these columns: *Task · Tool · Accuracy (1–5) · Followed constraints (1–5) · Voice (1–5) · Indian context (1–5) · Notes.* Decide which output you would actually use, and why.

**Deliverable:** the opening prompt, both outputs (links or screenshots), and your comparison row. Keep this sheet — it becomes part of your Project Block 1 submission.

## Common mistakes

- **Uploading a file and then asking a question the file does not answer.** The assistant will improvise. Ask it to say "not in the document" when that is the case.
- **Using memory for sensitive data.** Memory is convenient for "I study B.Com in Hassan", not for health details or other people's information.
- **Treating voice mode as a toy.** For interview practice and language fluency it is one of the most valuable features in the whole toolkit (Module 8).

## Key takeaways

- Learn the whole chat interface: files, images, search, voice, data tools, canvas, memory, sharing.
- One job per chat; reset when the conversation drifts; important information first and last.
- Supply what the model cannot know: audience, material, constraints, standard.
- Compare assistants with your own evidence log rather than online rankings.
- Replace the five bad habits with precise verbs, an audience, one question at a time, iteration and specific feedback.

## Reflection journal

Write 120 words: *What did the two assistants do differently on your task? Which difference would matter most in a workplace, and why?*

## Going further (optional)

- Explore the "share chat" feature and send a conversation to a classmate for review — a habit you will rely on in group projects.
