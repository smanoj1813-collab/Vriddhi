# 5.3 Low-code automation with AI steps

> **Lesson plan** · 90 minutes — Read 30 · Lab 50 · Quiz 10

## Learning objectives

By the end of this lesson you will be able to:

- Explain the building blocks of automation platforms: triggers, actions, filters, paths, formatters and AI steps.
- Compare Zapier, Make, n8n and native options (Google Sheets + AI, Microsoft Power Automate) and pick one for a task.
- Design an automation on paper before building it, including failure handling.
- Build three starter automations, at least one with an AI step, and test them end to end.
- Recognise the risks — runaway loops, data exposure, silent failures — and mitigate them.

## Opening scenario

The events secretary of a college club spends every Sunday copying registrations from a Google Form into a sheet, writing confirmation emails, and sorting participants into WhatsApp groups by track. A B.Com classmate builds an automation: new form response → AI step classifies the free-text "interest" field into one of four tracks → row added to the right tab → personalised confirmation email sent in English or Kannada depending on the response → Sunday summary posted to the organisers' group. Setup: one evening. Sundays: returned. The secretary now asks *"could we automate…"* about everything — which is exactly the right instinct, and Lesson 5.4 teaches when the answer should be no.

## Core ideas

### 1. The vocabulary of automation

Every automation platform uses the same ideas:

| Block | What it is | Example |
| --- | --- | --- |
| **Trigger** | The event that starts the run | New form response; new email with attachment; every day at 9 am; new row in a sheet |
| **Action** | Something the platform does | Send email; add row; create calendar event; post message; create document |
| **Filter / condition** | Continue only if… | Only if amount > 5,000; only if language = Kannada |
| **Paths / router** | Branch into different actions | Track A → group A; Track B → group B |
| **Formatter** | Transform data between steps | Date formats; split name; extract number; text case |
| **Delay / schedule** | Wait or run at a time | Reminder 2 days before the event |
| **Iterator / loop** | Do something for each item in a list | For each attendee, send a certificate |
| **AI step** | A model call inside the flow | Classify, extract, summarise, draft, translate |
| **Error handler** | What to do when a step fails | Notify owner; retry; write to an "errors" tab |

A **run** is one pass through the workflow; platforms bill by runs or "operations", which drives tool choice.

### 2. Choosing a platform

| Platform | Strengths | Free tier reality (2026) | Choose it when |
| --- | --- | --- | --- |
| **Zapier** | Easiest; thousands of app connections; built-in AI steps and "agents" | Small monthly task quota; multi-step flows often need a paid plan | You need it working today with mainstream apps |
| **Make** | Visual, powerful branching and iteration; generous operations | Reasonable free tier for learning | Flows with branching, loops and data shaping |
| **n8n** | Open source; self-hostable; strong AI/agent nodes; no per-run cost when self-hosted | Cloud trial limited; free if you run it yourself (or a college server) | Privacy-sensitive data, higher volume, or you want to learn the most transferable skill |
| **Google Sheets + AI functions / Apps Script** | Everything lives in the sheet; AI formulas (`=AI(...)` in Workspace where available, or add-ons) | Free with a Google account; Workspace features vary | Data already in Sheets; simple classification or drafting per row |
| **Microsoft Power Automate + Copilot** | Deep Microsoft 365 integration; Forms, Outlook, Teams, Excel | Included with many institutional 365 accounts | Your college or employer runs on Microsoft |

Rule for this course: **learn one platform well (Make or n8n recommended), and know Sheets-based AI for quick wins.**

### 3. Design on paper first

For every automation, fill this card before touching a tool:

```text
NAME:            Registration triage
TRIGGER:         New Google Form response (Event registration)
INPUTS:          name, email, phone, language, free-text interest
STEPS:
  1. AI step: classify interest into {Finance, Marketing, Design, Tech}; return
     JSON {track, confidence}
  2. Router by track → add row to the track's tab
  3. Filter: if confidence < 0.6 → add to "Review" tab and stop
  4. AI step: draft confirmation in the chosen language from a fixed template
     (do not invent dates; use the sheet values)
  5. Send email; log row with status
OUTPUTS:         row, email, weekly summary
HUMAN CHECKPOINT: low-confidence rows reviewed by secretary daily
FAILURE MODES:   email bounce → log; AI returns invalid JSON → route to Review;
                 duplicate submission → filter on email
VOLUME/COST:     ~150 runs/event; within free tier
DATA:            personal data (name, phone) — sheet access restricted; no AI
                 step receives phone numbers
```

The card is the deliverable a manager will read; the flow is the implementation.

### 4. AI steps done right

AI steps inside automations must be **narrow, structured and checked**, because nobody is watching each run:

- **One job per step**: classify *or* extract *or* draft. Chain steps rather than writing one huge prompt.
- **Structured output**: demand JSON or a fixed set of labels; validate with a filter before using the output ("if track is not one of the four, go to Review").
- **Templates for anything customer-facing**: the model fills slots; it does not free-write dates, prices or promises.
- **Few-shot examples** in the prompt for classification consistency (Lesson 2.3).
- **Confidence and fallback**: ask the model to return a confidence; route low-confidence items to a human.
- **Minimise data**: send the model only the fields it needs; never phone numbers, IDs or full records unless required and permitted.
- **Log every AI output** to a sheet so you can audit it later.

### 5. Three starter automations

**A. Inbox triage.** Trigger: new email with a label or to a shared inbox → AI step: classify {enquiry, complaint, invoice, spam} + one-line summary → router: complaints to a sheet and an alert; invoices to a Drive folder; enquiries get a templated acknowledgment → daily digest.

**B. Form → personalised response (the scenario above).**

**C. Content pipeline.** Trigger: new row in a "Content ideas" sheet → AI step: draft a caption in the brand voice from a template + three hashtags → write back to the row with status "Draft" → notify you → *human approves by changing status to "Approved"* → second flow posts or schedules. Never auto-publish without the approval step.

Others worth knowing: meeting notes → action items → tasks; receipt photo → extracted fields → expense sheet; daily news on a topic → summary to WhatsApp/Telegram; new PDF in a folder → summary and tags.

### 6. Risks and how to contain them

- **Runaway loops** (a flow that triggers itself, or sends 400 emails): test with a filter limiting to your own email; set run limits; keep a kill switch (turn the flow off) handy.
- **Silent failures**: a step fails and nobody notices for a month. Add an error handler that notifies you and a weekly "runs completed" summary.
- **Data exposure**: every connected app and AI step is a place data flows. Map it in the card; restrict access; avoid consumer AI steps for personal data; check the platform's data-region and retention (Lesson 7.4).
- **Credential sprawl**: use dedicated accounts for automations where possible; revoke access when the project ends.
- **Over-automation**: a wrong template sent perfectly to everyone is worse than a slow human. Human checkpoints on anything external or irreversible (Lesson 5.4).

## Try it now

In your chosen platform, build the smallest possible flow: **Trigger** — new row in a Google Sheet with a column "text" → **AI step** — "Classify the sentiment of this text as Positive, Neutral or Negative. Reply with one word." → **Action** — write the label to the next column. Add five rows. Watch the runs. Then break it on purpose (add a row with an empty "text") and see what the platform shows you.

## Hands-on lab: build and test one real automation (50 min)

1. **Pick (5 min)** one of the three starter automations, adapted to a real need you have (club, internship, family business, your own studies).
2. **Design card (10 min):** complete every field, especially failure modes, human checkpoint and data.
3. **Build (25 min):** trigger, AI step with structured output and validation filter, actions, error handler that emails you. Use test data addressed only to yourself.
4. **Test (10 min):** run at least five normal cases, two edge cases (empty field, wrong language) and one failure (disconnect an app or feed invalid data). Record what happened and what you changed.

**Deliverable:** the design card, a screenshot of the flow, the test log, and a 60-second screen-recorded demo (you will need this format for PB4). Add the design card template to your playbook.

## Common mistakes

- **Building before designing.** You will rebuild three times.
- **One giant AI prompt doing everything.** Narrow steps with validation.
- **Auto-sending to real people during testing.** Filter to your own address until proven.
- **No error handler.** Silent failure is the default.
- **Sending personal data to an AI step because it was in the row.** Minimise fields.

## Key takeaways

- Automations are triggers, actions, filters, routers, formatters, delays, iterators, AI steps and error handlers; platforms differ mostly in polish and pricing.
- Learn one platform well (Make or n8n) plus Sheets-based AI for quick wins.
- Design on a card first: inputs, steps, human checkpoint, failure modes, volume, data.
- AI steps must be narrow, structured, validated, templated for external content, data-minimised and logged.
- Contain risk: loops, silent failures, data exposure, credential sprawl, over-automation.
