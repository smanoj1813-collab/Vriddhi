# Facilitator guide — VPM-101 Project Management

Version 1.0.0 · Authored pack date 2026-09-28. Verify tool access and applicable guidance before each cohort; this is not a claim of external accreditation or independent legal review.

## 1. Audience and delivery model

A beginner, job-oriented 60-hour course for undergraduate learners preparing for Project Coordinator, PMO Analyst, Operations Associate. No coding, paid subscription or real organisational dataset is required. Teach with a shared computer lab, a spreadsheet and a document editor; named software can be replaced by an equivalent workflow with the same evidence.

There are eight modules, 24 lessons, four project blocks and one 12-hour capstone. Each lesson has five formative MCQs and a three-slide conceptual walkthrough. Each module has ten advanced scenario questions and a 60% pass gate. In total the pack contains 200 quiz items and 72 slides. Slides support understanding but do not substitute for reading completion, lab work or quizzes.

## 2. Preparation checklist

- Confirm the course is assigned to the intended college/programme through the existing Course assignments panel. Adding a bundled pack does not make it visible to all students automatically.
- Test the public overview and one protected learner journey using an authorised test account; verify the first lesson, quiz, slides and module gate.
- Copy the synthetic practice data into a clean workbook and independently reproduce the published checkpoints.
- Prepare a sandbox or offline board/dashboard template. Do not connect a production Jira project, payroll system or applicant database.
- Set an institution-approved submission folder, access roles, retention/deletion plan and feedback route. The app does not upload or mark project files.
- Publish attendance rules, due dates, accessibility arrangements, final-exam conditions and the distinction between platform completion and institutional award.
- Prepare and second-review the unseen final paper under the blueprint; do not commit secure questions or learner marks into this repository.

## 4. Session pattern

Start with the decision question and ask learners for an initial answer. Demonstrate a small worked example, then let learners reconstruct it. Protect the 40-minute lab block in each lesson. Use paired review with alternating preparer and reviewer roles; each learner keeps their own artefact and can explain it independently.

The standard lesson allocation is 25 minutes reading/discussion, ten minutes worked example, forty minutes lab, and fifteen minutes quiz/reflection. Across a module, redistribute the review allocation to include its mini-assessment. If extra support is needed, provide optional lab time rather than silently reducing required learning outcomes.

Ask “what would make this conclusion wrong?” regularly. Reward correct limitations and transparent corrections. Do not reward invented real-world results, overconfident causal claims or a dashboard that hides missing information. Keep reflection private by default; learners may share only selected excerpts for peer feedback.

## 5. Module teaching notes

### Module 1 — Project foundations and stakeholder decisions

Translate a business request into a bounded project, an approval route and a measurable definition of success. Demonstrate the worked example in each lesson, then ask learners to reproduce it before changing an assumption. Watch especially for: Treating installation as proof of a benefit.; Confusing a charter with permission already granted.; Using power as the only reason to listen to someone. Record one correction and one remaining question in the cohort review log.

### Module 2 — Planning, scheduling and cost

Build a deliverable-based plan with dependencies, realistic capacity and a controlled cost baseline. Demonstrate the worked example in each lesson, then ask learners to reproduce it before changing an assumption. Watch especially for: Using task names as proof that all scope is covered.; Calling the busiest person the critical path.; Equating underspend with good performance. Record one correction and one remaining question in the cohort review log.

### Module 3 — Agile and Scrum practice

Choose an adaptive approach, apply Scrum accountabilities and use empirical feedback without ritual-driven management. Demonstrate the worked example in each lesson, then ask learners to reproduce it before changing an assumption. Watch especially for: Claiming Agile means no documentation.; Making the Daily Scrum a sponsor status report.; Converting every story point into a fixed hour. Record one correction and one remaining question in the cohort review log.

### Module 4 — Jira and flow-based execution

Translate an agreed workflow into a practical board and use flow measures to reveal bottlenecks, not monitor individuals. Demonstrate the worked example in each lesson, then ask learners to reproduce it before changing an assumption. Watch especially for: Assuming every Jira site has the same menus or issue names.; Interpreting zero results as proof that work is healthy.; Treating a WIP limit as a staff utilisation target. Record one correction and one remaining question in the cohort review log.

### Module 5 — Risk, quality and change control

Keep uncertainty, current issues, acceptance evidence and scope decisions visible and owned. Demonstrate the worked example in each lesson, then ask learners to reproduce it before changing an assumption. Watch especially for: Mixing issues and risks without indicating status.; Using pass rate as the only release criterion.; Estimating only coding effort for a new feature. Record one correction and one remaining question in the cohort review log.

### Module 6 — PMO reporting and governance

Create a reconciled status pack and facilitate decisions with useful measures, clear minutes and portfolio context. Demonstrate the worked example in each lesson, then ask learners to reproduce it before changing an assumption. Watch especially for: Averaging away a red critical risk.; Writing recommendations as if they were authorised decisions.; Treating a weighted score as an automatic approval. Record one correction and one remaining question in the cohort review log.

### Module 7 — Operations, vendors and transition

Design sustainable service handovers, supplier controls and small improvement experiments. Demonstrate the worked example in each lesson, then ask learners to reproduce it before changing an assumption. Watch especially for: Using theoretical maximum capacity as a guaranteed service level.; Comparing headline prices with different inclusions.; Equating go-live with complete handover. Record one correction and one remaining question in the cohort review log.

### Module 8 — Capstone and career readiness

Integrate the delivery evidence into a credible portfolio for Project Coordinator, PMO Analyst and Operations Associate roles. Demonstrate the worked example in each lesson, then ask learners to reproduce it before changing an assumption. Watch especially for: Calling simulated benefits real savings.; Giving only definitions instead of actions.; Confusing a course completion certificate with an external credential. Record one correction and one remaining question in the cohort review log.

## 6. Projects, marking and capstone

Project briefs provide time budgets, outputs, checkpoints and AI-use templates. Use the published rubrics and return block feedback within ten days where feasible. Moderate at least 20% of work and every borderline capstone/award case. Where group work is allowed, collect individual contributions and oral evidence before assigning marks.

Begin capstone framing before the final two weeks so learners can reuse checked artefacts. The capstone is twelve hours of integration, analysis, review and presentation—not merely a short final pitch. Each learner presents for five minutes and answers individual evidence questions; reserve the remainder of the allocated presentation/reflection hour for preparation, peer review and revisions. Require at least two reproduced calculations or decisions.

## 7. Accessibility and common difficulties

| Difficulty | Response |
| --- | --- |
| Limited software or internet | Use the offline spreadsheet/board route; screenshots are not mandatory if equivalent records are inspectable |
| Arithmetic anxiety | Reproduce one small example by hand, then link the same inputs in a sheet |
| English fluency | Permit Kannada or Hindi reflection/presentation by arrangement; keep numbers and definitions clear |
| Confusing a rate, a count or an estimate | Return to the metric/decision dictionary and ask what the denominator or assumption represents |
| Treating a tool output as truth | Compare it with a known fixture and a manual check |
| Overusing AI-generated prose | Require the learner to reproduce the method and explain accepted/rejected suggestions |
| Portfolio overclaiming | Label the simulation and distinguish actions performed from business outcomes not observed |

## 8. Source and tool maintenance

The lesson links point to primary product guidance, framework documentation and professional reference material. Check them before delivery and record access dates in the cohort log. Jira terminology and available features can differ by site; spreadsheet functions and sharing permissions can differ by version. Do not promise a free tier or a particular menu path. Check applicable privacy and employment requirements with qualified institutional staff rather than treating course examples as legal advice.

If a question or worked answer is wrong, record the correction, review related items and apply fair cohort-wide marking adjustments. Bump the pack version for material changes. Never change pass conditions or weights retroactively during a cohort without a documented learner-protective process.

## 9. Completion administration

Maintain institutional attendance, project marks, final marks and integrity decisions separately from platform reading/quiz progress. Verify institutional award conditions under the certification policy. The platform’s certificate eligibility is a learning-progress checklist, not an automatic verification of externally marked work. All learner records belong in approved college systems, not in course-content files or public PR comments.
