# 6.2 Google Analytics 4 essentials

> **Lesson plan** · 90 minutes — Read 30 · Lab 45 · Quiz 15

## Learning objectives

By the end of this lesson you will be able to:

- Explain what GA4 actually measures, using the event model.
- Install and verify GA4 on a real site and confirm events arriving.
- Use reports, comparisons and exploration to answer five marketing questions.
- Set up the conversions that matter, without drowning in configuration.

## Opening scenario

A Bengaluru study-abroad consultancy's website had GA4 installed by the developer two years ago. Nobody had opened it since. When a marketing student finally logged in, she found the property collecting "page_view" events — and nothing else. Thousands of visitors, zero information: no form submissions, no call-button clicks, no WhatsApp taps, no scroll depth. The tool was on; the measurement was off.

GA4 is the most widely installed analytics tool in the world and the most widely ignored. This lesson makes it earn its keep: enough events, the right conversions, and the five questions it answers well.

## Core ideas

### 1. The event model: everything is an event

Old analytics counted visits. GA4 counts **events** — every action a user takes:

- `page_view` — a page loaded
- `session_start` — a visit began
- `form_start` / `form_submit` — a form began / completed
- `click` (with a parameter naming the link) — an outbound link, a WhatsApp button, a phone tap
- `scroll` — the user reached 90% of a page
- `view_item`, `add_to_cart`, `purchase` — commerce actions

Each event carries **parameters** (which page, which link, what value). Users, sessions and pages become aggregations of events rather than separate categories. One vocabulary covers everything — which matters the moment you go beyond a website, because app and web now speak the same language.

### 2. Installation and verification

Setup is two steps and one discipline:

1. **Create the property** in the GA4 admin (name it after the business, select India/timezone, industry category). GA4 shows a **Measurement ID** like `G-XXXXXXXXXX`.
2. **Install the tag** — either in the site's `<head>` directly, or via Google Tag Manager (GTM), the safer route for sites where you cannot or should not edit code. For WordPress, plugin routes exist; for hosted builders, paste the ID into their integrations panel.
3. **Verify** with **DebugView** (real-time stream of your own clicks as you browse) and the **Realtime report**. Rule: an unverified installation does not exist. Common failures — tag in the wrong property, a typo in the ID, a second analytics plugin silently overwriting yours.

### 3. The five questions GA4 answers well

Everything GA4 offers compresses to five questions:

1. **Who is visiting?** Reports → User attributes. Country/city (Bengaluru vs others), device, language. A 60% mobile audience with a desktop-designed site is a finding.
2. **Where do they come from?** Reports → Acquisition → Traffic acquisition, segmented by **session source/medium**: `google/organic`, `l.google` (paid Ads), `instagram.com / referral`, `(direct)/(none)`. This is where SEO and social efforts become visible — the numbers behind Module 2 and Module 5.
3. **What do they do?** Reports → Engagement: pages and screens (which pages hold attention), events count, average engagement time. The **Landing page** report pairs with acquisition to show which entrance converts.
4. **Do they convert?** Conversions — see below.
5. **Do they come back?** Retention reports: new vs returning, the cohorts that return.

**Explorations** (the drag-and-drop workspace beyond standard reports) answers custom questions: e.g., build a table of landing page × session source × conversion rate to find which page earns which channel.

### 4. Conversions: the configuration that matters

GA4 calls an important event a **key event** (conversion). You can mark built-in events or register custom ones — `form_submit` on the enquiry form, a click on the WhatsApp anchor, a `generate_lead` event fired by the form's thank-you page.

Priorities, in order:

1. One conversion that proxies the business action (enquiry, WhatsApp start, booking). If you configure nothing else, configure this.
2. **Enhanced measurement** left ON (outbound clicks, site search, scroll, video — free, automatic).
3. Google Ads linking (Module 4's conversions then flow both ways), and Google Search Console linking (query data in GA4 — Module 2's world).

What you resist matters as much: don't create 40 conversions; don't measure page views as conversions (that's the vanity trap from Lesson 6.1 wearing a configuration costume).

### 5. Reading honestly: consent, sampling, attribution noise

Three honesty clauses. **Consent:** GA4 respects consent banners; with a Consent Mode banner, some sessions are modelled — good for privacy, means numbers are estimates at the edges. **Sampling:** huge explorations over long ranges may sample. **Attribution:** GA4's default is data-driven attribution — reasonable, not gospel (Lesson 6.4 goes deeper). Treat GA4 numbers as the best available estimate, not an audit.

## Try it now

Open any website and view its page source (Ctrl+U); search for "gtag" or "GTM-". You will find most commercial sites have analytics installed — you now know what it is hearing.

## Hands-on lab: GA4, live (45 min)

1. **Sandbox (10 min):** Use the GA4 demo account (Google's "GA4 Demo – For Google Merchandise Store", accessible from GA4's help) OR any site you control. Find: Traffic acquisition, Engagement → Landing page, Realtime.
2. **Read acquisition (10 min):** In Traffic acquisition, identify the top three source/medium rows. Write one sentence per row ("organic search brings the most sessions; social brings X%").
3. **Comparisons (10 min):** Add a comparison (e.g., Device = mobile vs desktop). Note one difference in behaviour — pages per session or engagement time.
4. **Design your own (15 min):** For your Project Block 3 business, write the event plan: which 5 events you'd want (built-in or custom), which ONE becomes the key event, and the source/medium labels you expect from your campaign channels.

> **Deliverable:** Screenshot-free summary: acquisition top-3, comparison finding, and your 5-event plan with the key event starred. Project Block 4's dashboard consumes exactly this.

## Common mistakes

- **Install-and-abandon.** The tag exists; nobody configured conversions. Zero information.
- **Page views as conversions.** Vanity in a costume.
- **Quoting GA4 as gospel.** Consent mode and modelling make edges soft; say "about".
- **Exploring before reporting.** Standard reports answer 80% of questions; explorations reward the patient, not the impatient.

## Key takeaways

- GA4's event model records actions with parameters; users and sessions are aggregations.
- Install → verify in Realtime/DebugView; an unverified installation does not exist.
- Five questions: who, from where, what, do they convert, do they return.
- Configure ONE business-proxy key event first; link Search Console and Ads; leave enhanced measurement on.
