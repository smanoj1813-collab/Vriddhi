# Project Block 4 — Analytics Dashboard and Insight Log

> **Project plan** · 60 minutes guided + 3–4 hours independent work · Submit by the end of Week 8 · Weight: 7% of the final grade

## The brief

A Bengaluru boutique fitness studio runs Google Ads, posts daily on Instagram, and collects enquiries through a website form and WhatsApp. The owner's entire analytics stack is a developer-installed GA4 nobody has opened and a folder of screenshots. She asks for one thing: *"Tell me what's working — every week, without me asking."*

You will deliver exactly that: a measurement design, a working dashboard, and the first month of an insight log — the operating rhythm that turns Module 6 into a deliverable employers recognise.

This project uses your Project Block 3 campaign as the subject. If you have real data (your own site, a client's, or the GA4 demo property), use it. Where real data is missing, simulate honestly and label it "simulated" — never fabricate numbers and present them as real.

## What to submit

1. **The KPI tree** (diagram or clean indented text) for the studio or your PB3 business: goal, 3+ channel branches with diagnostics, conversion KPI, CPA guardrail. Every number's source named (GA4, ads platform, manual sheet).
2. **The event plan:** five events you would track (built-in or custom), the ONE key event that proxies the business action, and the verification step you would run after installation.
3. **The dashboard:** a Looker Studio page (screenshot or share link) or a fully-built spreadsheet with the five panels — header KPIs vs previous period, trend with target, channel breakdown, funnel, insight notes. If using the GA4 demo property, state so.
4. **The insight log:** four weekly entries in a table — date, metric moved, diagnosis, action, owner. Entries may come from your PB3 campaign or be simulated and labelled.
5. **The incrementality design:** one cheap check (pause test, geo split, or how-did-you-hear log) — what you would compare, for how long, and what result would change a budget decision.
6. **The A/B test plan:** hypothesis with one change and one mechanism, split mechanism, sample-size estimate (name the calculator and inputs), duration, decision rule written in advance.
7. **The automation choices:** delivery cadence, recipients, scheduled PDF or shared link, and one alert you would configure (GA4 insight or ads-platform alert).
8. **The client email (≤150 words):** three sentences of findings, one recommendation, one ask. Written for a non-technical owner.
9. **The AI-use statement:** which AI tools helped, where, and what you verified by hand.

## Coverage requirements

Your submission must visibly use: the decision-metric test (Lesson 6.1), the event model and key-event choice (6.2), the five-panel structure and automation (6.3), and attribution honesty or experimental thinking (6.4). A submission that is all dashboard and no insight log fails the brief — the log is the deliverable.

## Process

| Step | Guidance | Time |
|---|---|---|
| 1 | Draw the KPI tree; mark each source | 30 min |
| 2 | Verify/choose your data source; connect it | 45 min |
| 3 | Build the five panels; title each as a question | 90 min |
| 4 | Write the four insight-log entries | 30 min |
| 5 | Design incrementality check + A/B plan | 30 min |
| 6 | Draft the client email; check it against the honesty rules | 15 min |

## Rubric

| Criterion | 0–1 · Missing | 2 · Developing | 3 · Professional |
|---|---|---|---|
| Measurement design | Tree incomplete or missing sources | Tree complete; sources vague | Goal → channels → diagnostics complete, every number sourced, CPA guardrail set |
| Dashboard | Panels missing or decorative | Five panels present; titles are metric names | Five panels titled as questions; comparisons on; manual layer included |
| Insight log | Fewer than four entries or no actions | Four entries; actions generic | Four entries with diagnosis, dated actions, owners; entries reference dashboard evidence |
| Attribution and experiments | Neither present | One present but loosely designed | Incrementality check realistic; A/B plan has one change, sample size, pre-written decision rule |
| Client communication | Jargon or missing | Understandable but hedged | Three findings, one recommendation, one ask — no vanity metrics quoted |
| Honesty | Fabricated numbers presented as real | Some simulation unlabelled | All simulated data labelled; GA4 quoted as estimate |
| AI use | No statement | Statement vague | Tools named, uses specific, verification described |

**Pass mark: 4 of 7 criteria at professional (3).** The dashboard link or screenshots must open for the assessor.
