# Facilitator guide — VHR-101 HR Analytics

Version 1.0.0 · Authored pack date 2026-09-28. Verify tool access and applicable guidance before each cohort; this is not a claim of external accreditation or independent legal review.

## 1. Audience and delivery model

A beginner, job-oriented 60-hour course for undergraduate learners preparing for HR Executive, HR Analyst, Talent Acquisition Associate. No coding, paid subscription or real organisational dataset is required. Teach with a shared computer lab, a spreadsheet and a document editor; named software can be replaced by an equivalent workflow with the same evidence.

There are eight modules, 24 lessons, four project blocks and one 12-hour capstone. Each lesson has five formative MCQs and a three-slide conceptual walkthrough. Each module has ten advanced scenario questions and a 60% pass gate. In total the pack contains 200 quiz items and 72 slides. Slides support understanding but do not substitute for reading completion, lab work or quizzes.

## 2. Preparation checklist

## 4. Session pattern

Start with the decision question and ask learners for an initial answer. Demonstrate a small worked example, then let learners reconstruct it. Protect the 40-minute lab block in each lesson. Use paired review with alternating preparer and reviewer roles; each learner keeps their own artefact and can explain it independently.

The standard lesson allocation is 25 minutes reading/discussion, ten minutes worked example, forty minutes lab, and fifteen minutes quiz/reflection. Across a module, redistribute the review allocation to include its mini-assessment. If extra support is needed, provide optional lab time rather than silently reducing required learning outcomes.

Ask “what would make this conclusion wrong?” regularly. Reward correct limitations and transparent corrections. Do not reward invented real-world results, overconfident causal claims or a dashboard that hides missing information. Keep reflection private by default; learners may share only selected excerpts for peer feedback.

## 5. Module teaching notes

### Module 1 — People analytics foundations and responsible questions

Translate an HR concern into an answerable question with a clear population, decision and privacy boundary. Demonstrate the worked example in each lesson, then ask learners to reproduce it before changing an assumption. Watch especially for: Starting with a chart before knowing the decision.; Counting offer acceptances as joined employees.; Calling an ID-coded employee dataset anonymous. Record one correction and one remaining question in the cohort review log.

### Module 2 — Data preparation and spreadsheet analysis

Create a reproducible cleaning workflow and use transparent spreadsheet calculations before interpreting people metrics. Demonstrate the worked example in each lesson, then ask learners to reproduce it before changing an assumption. Watch especially for: Deduplicating by a key that does not match the row grain.; Suppressing all formula errors as zero.; Deleting a genuine outlier because it is inconvenient. Record one correction and one remaining question in the cohort review log.

### Module 3 — Recruitment funnel and selection analytics

Measure recruitment stages and costs with consistent cohorts while preserving fair, structured human selection. Demonstrate the worked example in each lesson, then ask learners to reproduce it before changing an assumption. Watch especially for: Dividing events from different cohorts without labelling the method.; Using identical labels for different clocks.; Using “culture fit” without job-related evidence. Record one correction and one remaining question in the cohort review log.

### Module 4 — Workforce planning and core HR metrics

Reconcile headcount, FTE, turnover and attendance measures before building a scenario-based workforce plan. Demonstrate the worked example in each lesson, then ask learners to reproduce it before changing an assumption. Watch especially for: Treating FTE as a rating of individual value.; Assuming retention always equals one minus turnover.; Counting offer acceptances as guaranteed available capacity. Record one correction and one remaining question in the cohort review log.

### Module 5 — Engagement, retention and development

Interpret employee feedback and cohort outcomes without confusing association with causation or exposing individuals. Demonstrate the worked example in each lesson, then ask learners to reproduce it before changing an assumption. Watch especially for: Calling a practice survey a validated psychological test.; Treating recent employees as fully observed survivors.; Calling attendance proof of learning. Record one correction and one remaining question in the cohort review log.

### Module 6 — Dashboards and HR storytelling

Build accessible, auditable dashboards that connect a small set of trustworthy measures to responsible decisions. Demonstrate the worked example in each lesson, then ask learners to reproduce it before changing an assumption. Watch especially for: Starting from every field available instead of an audience question.; Filtering only the numerator.; Using a dramatic relative change without absolute counts. Record one correction and one remaining question in the cohort review log.

### Module 7 — Responsible people analytics and evaluation

Understand confounding, predictive-model limits and fair-use checks before proposing interventions affecting people. Demonstrate the worked example in each lesson, then ask learners to reproduce it before changing an assumption. Watch especially for: Calling every correlation a cause.; Using accuracy alone on an imbalanced outcome.; Inferring protected characteristics from names. Record one correction and one remaining question in the cohort review log.

### Module 8 — HR analytics capstone and career launch

Present a reproducible, privacy-safe portfolio for HR Executive, HR Analyst and Talent Acquisition Associate roles. Demonstrate the worked example in each lesson, then ask learners to reproduce it before changing an assumption. Watch especially for: Claiming simulated outcomes as real employer impact.; Assuming seniority alone authorises every data request.; Treating course completion as an external professional credential. Record one correction and one remaining question in the cohort review log.

## 6. Projects, marking and capstone

Project briefs provide time budgets, outputs, checkpoints and AI-use templates. Use the published rubrics and return block feedback within ten days where feasible. Moderate at least 20% of work and every borderline capstone/award case. Where group work is allowed, collect individual contributions and oral evidence before assigning marks.

Begin capstone framing before the final two weeks so learners can reuse checked artefacts. The capstone is twelve hours of integration, analysis, review and presentation—not merely a short final pitch. Each learner presents for five minutes and answers individual evidence questions; reserve the remainder of the allocated presentation/reflection hour for preparation, peer review and revisions. Require at least two reproduced calculations or decisions.

## 7. Accessibility and common difficulties

| Difficulty | Response |
| --- | --- |
| Limited software or internet | Use the offline spreadsheet/board route; screenshots are not mandatory if equivalent records are inspectable |
| Arithmetic anxiety | Reproduce one small example by hand, then link the same inputs in a sheet |
| English fluency | Permit Kannada or Hindi reflection/presentation by arrangement; keep numbers and definitions clear |
| Confusing a rate, a count or an estimate | Return to the metric/decision dictionary and ask what the denominator or assumption represents |
| Treating a tool output as truth | Compare it with a known fixture and a manual check |
| Overusing AI-generated prose | Require the learner to reproduce the method and explain accepted/rejected suggestions |
| Portfolio overclaiming | Label the simulation and distinguish actions performed from business outcomes not observed |

## 8. Source and tool maintenance

The lesson links point to primary product guidance, framework documentation and professional reference material. Check them before delivery and record access dates in the cohort log. Jira terminology and available features can differ by site; spreadsheet functions and sharing permissions can differ by version. Do not promise a free tier or a particular menu path. Check applicable privacy and employment requirements with qualified institutional staff rather than treating course examples as legal advice.

If a question or worked answer is wrong, record the correction, review related items and apply fair cohort-wide marking adjustments. Bump the pack version for material changes. Never change pass conditions or weights retroactively during a cohort without a documented learner-protective process.

## 9. Completion administration

Maintain institutional attendance, project marks, final marks and integrity decisions separately from platform reading/quiz progress. Verify institutional award conditions under the certification policy. The platform’s certificate eligibility is a learning-progress checklist, not an automatic verification of externally marked work. All learner records belong in approved college systems, not in course-content files or public PR comments.
