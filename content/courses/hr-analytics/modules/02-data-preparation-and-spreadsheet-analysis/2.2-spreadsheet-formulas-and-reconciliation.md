# 2.2 Spreadsheet formulas and reconciliation

> **Lesson plan** · 90 minutes — Read and discuss 25 min · Worked example 10 min · Hands-on lab 40 min · Quiz and reflection 15 min.

## Learning objectives

By the end of this lesson you can:

- Use transparent formulas and denominator checks to calculate grouped HR measures.
- Produce a reviewable formula workbook with audit checks using the supplied practice case.
- Explain one limitation, one verification check and the next decision the evidence supports.

## Opening scenario

The HR team needs joined candidates by source and offer acceptance by department. A manually typed summary is quick, but it will not update when a record changes. A reliable workbook needs consistent tables, documented filters and visible checks.

Namma People Services is a fictional organisation created for this course. All employee IDs, applications, costs, survey responses and workforce events are synthetic. The exercises model decisions an entry-level HR team might support, but they do not authorise live selection, dismissal, health inference or individual employee-risk scoring. Use the supplied practice records rather than collecting real personal data.

Write your initial recommendation before analysing the case. Keep it for comparison after the lab: what did the evidence change, and why?

## Core ideas

### 1. Use formulas appropriate to the question

COUNTIFS counts records matching conditions; SUMIFS aggregates numeric values by conditions; lookup functions connect reference fields using keys. Use exact-match lookups for identifiers and inspect unmatched keys. Spreadsheet function availability varies, so an equivalent pivot or carefully documented manual method is acceptable. Lock reference ranges when copying formulas where needed, and keep source values separate from calculated outputs.

### 2. Guard denominators explicitly

A rate is numerator divided by an eligible denominator over a defined period or cohort. If no offers were issued, offer acceptance is not meaningfully zero percent; it is not applicable for that group. Use a conditional expression that displays a clear label and preserves the underlying counts. Avoid replacing every formula error with zero through a blanket error handler, because that can hide broken references or missing lookups.

### 3. Reconcile detail to summary

A grouped summary should reconcile to the same filtered total when categories are mutually exclusive and complete. Include an Unknown category where necessary rather than dropping blanks silently. Check formulas against a hand-calculated sample and test a changed input. Document whether counts represent applications or distinct people. A pivot table can summarise duplicates just as efficiently as clean records; aggregation does not solve data quality.

## Worked example

For Source A, 12 offers were issued and 9 accepted, so acceptance is 9/12 = 75%. Source B has no issued offers, so report “not applicable, n=0”, not 0%. If A has six joins, offer-to-join yield is 6/12 = 50%, while accepted-to-joined conversion is 6/9 ≈ 66.7%. These are different metrics and must have different labels.

### Reproduce before interpreting

Recreate the example from its inputs. Label units, show formulas or decision rules and keep an unchanged source copy. Change one assumption and identify which conclusion changes. Check one calculation or classification manually.

Test a relevant edge case: a missing date, zero denominator, incomplete observation or absent approval. Unknown information is not automatically zero or permission to invent a replacement. Record how the uncertainty affects your recommendation.

## Try it now

In pairs, explain the worked example without reading it aloud. The reviewer asks, “What evidence would change this recommendation?” Name the specific record, owner or observation you would request and how it could affect the decision. Swap roles and compare answers.

## Hands-on lab: formula workbook with audit checks (40 min)

Use the fictional case in this lesson. Do not contact real employees, candidates, customers or suppliers for these exercises. A spreadsheet, document and paper sketches are sufficient; named software is a convenience, not a requirement for marks.

1. Build counts by source for offers, acceptances and joins from the practice records.

2. Calculate acceptance and join conversion with explicit denominators.

3. Add an empty group to test zero-denominator behaviour.

4. Use a lookup or mapping table for department labels and list unmatched keys.

5. Reconcile grouped totals and hand-check two rates before writing a recommendation.

**Deliverable:** submit your formula workbook with audit checks, an assumptions note and a short recommendation. Use a descriptive filename containing the lesson number, your learner identifier and a revision number. Include the case period, units, source label “synthetic classroom case”, author and review date inside the artefact, not only in its filename.

### Lab review and acceptance

Reserve eight lab minutes for partner review. Trace one conclusion to its input, reproduce a calculation or classification and identify a possible misunderstanding. Keep the review comment and your correction or explanation in a two-column change log.

| Acceptance check | Evidence to leave in the submission |
| --- | --- |
| Scope is explicit | The question being answered and what is outside the exercise |
| Work can be reproduced | Source values, rules or formulas, and a manual check |
| Recommendation is actionable | Named role, next action and review trigger |
| Uncertainty is visible | An assumption and the effect if it proves false |
| Sharing is appropriate | Synthetic-data label and removal of unnecessary identifiers |

Working alone? Reopen the file as a reviewer. Check the version, evidence basis and distinction between observed facts and proposed actions.

## Common mistakes

- Suppressing all formula errors as zero.
- Giving different denominators the same conversion label.
- Assuming a pivot table removes duplicate source records.

Do not improve the appearance of a result by removing inconvenient records or changing an agreed definition halfway through the exercise. If the rule is wrong, propose a revision and show both versions. The goal is a defensible decision, not a perfect-looking chart or an artificially green status.

## Key takeaways

- **Use formulas appropriate to the question:** COUNTIFS counts records matching conditions; SUMIFS aggregates numeric values by conditions; lookup functions connect reference fields using keys.
- **Guard denominators explicitly:** A rate is numerator divided by an eligible denominator over a defined period or cohort.
- **Reconcile detail to summary:** A grouped summary should reconcile to the same filtered total when categories are mutually exclusive and complete.
